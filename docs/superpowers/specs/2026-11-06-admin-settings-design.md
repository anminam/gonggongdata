## 왜 하나

설정 화면 맨 아래 "관리자 설정" 영역(관리자에게만 보임)에는 원래 "메일 발송 계정"만 있었다.
코드에 박혀 있어서 바꾸려면 배포가 필요한 운영 값 세 가지를 관리자가 화면에서 바꿀 수 있게 한다.

1. 알림 메일 발송 일시정지
2. 가입 승인 방식
3. 알림 메일 제목 양식

## 목표 / 하지 않을 것

**목표**
- 세 설정을 설정 화면의 "관리자 설정" 영역에서 보고 바꾼다.
- 바꾼 값은 다음 자동 실행(매일 14:00 KST)이나 다음 가입부터 바로 적용된다. 재배포는 필요 없다.

**하지 않을 것**
- 수집 시각 변경 (vercel.json의 cron이라 화면에서 못 바꾼다)
- 메일 본문 문구 편집, 제목 양식 여러 개 저장해 고르기
- 수집 일시정지 (수집은 늘 돈다)

**실패로 보는 것 (동작은 해도 안 됨)**
- 일반 사용자가 설정을 읽거나 바꿀 수 있음
- 가입자가 브라우저에서 값을 조작해 스스로 승인됨
- 일시정지 중인데 자동 메일이 나감

## 1. 알림 메일 발송 일시정지 (사용자 결정: 수집은 계속, 발송만 멈춤)

- 스위치 하나: "자동 발송" 켬/끔. 기본은 켬. 저장 값은 `mail_paused`(기본 `false`).
- 끄면 `runDaily()`(`lib/run.ts`)가 수집·저장은 그대로 하고, 3단계(사용자별 발송)만 건너뛴다.
  - 실행 기록(`gd_run_logs`)은 평소처럼 남고, `emails_sent`는 0이다.
  - **구현:** 실행 기록에 "일시정지로 건너뜀"을 따로 남기는 컬럼은 추가하지 않았다. 대신 `runDaily()` 결과에 `mailPaused`를 담아 돌려준다.
- 관리자 페이지의 "지금 실행"(`/api/admin/run`)도 일시정지 중에는 수집만 하고 발송하지 않는다. *(사용자 결정)*
  - **구현:** 이때 토스트가 "발송 일시정지 중이라 메일은 보내지 않았어요"로 바뀐다 (`app/components/Admin.tsx`).
- 강제 재발송, 공지 지정 발송, 테스트 발송, 내 테스트 발송은 일시정지와 상관없이 그대로 동작한다. *(내 판단)*
- 다시 켜면: 코드가 "최근 7일 중 아직 안 보낸 공지"를 보내므로, 멈춘 동안 쌓인 최근 7일 공지는 다음 자동 실행 때 나간다. 7일보다 오래된 건 안 나간다. 이 동작을 바꾸는 코드는 추가하지 않았다. *(내 판단)*
- 화면: 꺼져 있을 때 "자동 알림 메일이 나가지 않아요. 수집은 계속돼요. 다시 켜면 최근 7일 중 못 보낸 공지가 다음 실행 때 나가요." 안내를 보여 준다.
- 테스트: `tests/run-daily.test.ts` (일시정지면 수집만, 아니면 평소처럼 발송).

## 2. 가입 승인 방식 (사용자 결정: 세 가지 중 선택)

- 선택지: **수동 승인**(`manual`, 기본) / **도메인 자동 승인**(`domain`) / **전원 자동 승인**(`all`)
- 도메인 자동 승인일 때는 허용 도메인 목록(`approval_domains`, 배열 컬럼)을 관리자가 넣고 뺀다 (예: `example.go.kr`).
  - 입력값은 앞의 `@`와 공백을 떼고 소문자로 저장한다. 점(`.`)이 없거나 공백·`@`가 남으면 거절한다 (`normalizeDomain`).
  - 일치는 정확히 같은 도메인만으로 한다. 하위 도메인은 포함하지 않는다. *(내 판단)*
  - 목록이 비어 있으면 아무도 자동 승인되지 않는다 (화면에 안내).
- 적용 시점: **새 가입(프로필 생성) 때만**. 이미 승인 대기 중인 사람을 한꺼번에 승인하지는 않는다. *(내 판단)*
- 자동 승인되면 `status = 'approved'`, `approved_at = now()`.
- 거절된 사람은 계정을 지우지 않고 `rejected` 상태로만 둔다. 그래서 다시 로그인해도 프로필이 이미 있어 재승인되지 않는다. 차단 목록은 만들지 않는다. *(사용자 결정)*

**보안 (구현됨)**
- 프로필 줄은 브라우저가 만든다 (`app/page.tsx`의 insert). 그래서 승인 판단은 DB가 한다.
- `gd_profiles`의 `BEFORE INSERT` 트리거 함수 `gd_profiles_before_insert()`(`security definer`)가 상태를 정한다.
  - 브라우저가 보낸 `status`, `approved_at`, `is_admin`, `email` 값은 무시하고 트리거가 덮어쓴다.
  - 도메인은 **`auth.users`의 로그인 이메일**로 판단하고, `gd_profiles.email`도 이 값으로 덮어쓴다 (기본 수신 주소 트리거가 남의 주소를 쓰지 않도록).
  - **추가(`e97b79b`):** 도메인 자동 승인은 `auth.users.email_confirmed_at`이 있는(인증된) 이메일일 때만 한다. 이메일 가입이나 다른 소셜 로그인으로 남의 도메인 주소를 써서 승인받는 것을 막는다. 전원 자동 승인에는 이 조건이 없다.
  - 관리자 계정 이메일은 트리거 안에서 항상 `approved` + `is_admin = true`로 처리한다 (기존 동작 유지).

## 3. 알림 메일 제목 양식 (사용자 결정: 제목 전체 + 칸 넣기)

- 관리자가 제목 전체를 한 줄로 쓴다. 칸은 두 개만 쓴다.
  - `{건수}` → 이번 메일에 들어간 공지 수 (숫자만, 예: `3`)
  - `{날짜}` → 발송일 (한국 시간, `YYYY-MM-DD`)
- 기본값은 원래 제목과 같다: `🚨 공공데이터 API 변경공지 감지 {건수}건 ({날짜})` (`DEFAULT_SUBJECT`)
- 비워 두면(`null`) 기본값을 쓴다. 없는 칸(예: `{기관}`)은 글자 그대로 남는다.
- 테스트 발송일 때 앞에 붙는 `[테스트] `는 코드가 자동으로 붙인다.
- 줄바꿈은 저장할 때 공백으로 바꾸고, 200자까지 자른다 (`cleanSubject`). DB에도 200자 check 제약이 있다. *(내 판단)*
- 화면: 입력칸 아래에 쓸 수 있는 칸을 안내하고, 오늘 날짜와 예시 건수 3으로 채운 미리보기를 보여 준다. 저장 버튼(또는 Enter)으로 저장.
- 적용 범위: `renderEmail(notices, test, subjectTemplate)` 한 곳에서 처리하고, 자동 발송·강제 재발송·공지 지정 발송·테스트 발송·내 테스트 발송이 모두 설정 값을 넘긴다.
- 테스트: `tests/settings.test.ts` (기본 제목, 칸 치환, 모르는 칸, 줄바꿈·200자, 도메인 정규화).

## 저장소와 권한 (구현됨)

- 테이블 `gd_app_settings`: 한 줄짜리(`id = 1` 고정, `gd_mail_sender`와 같은 방식).
  - 컬럼: `mail_paused`, `approval_mode`(check: manual/domain/all), `approval_domains text[]`, `subject_template`(≤200자), `updated_at`, `updated_by`
- **RLS 켬.** select·insert·update 모두 `public.gd_is_admin()`만 허용. `anon` 권한은 회수. delete 정책은 없음(아무도 못 지움).
- 서버(크론, 발송)는 service role로 `loadAppSettings()`를 통해 읽는다.
- 가입 트리거는 `security definer`라서 RLS와 상관없이 읽는다.
- 줄이 없거나 값이 `null`이면 기본값으로 동작한다 (발송 켬, 수동 승인, 기본 제목).

## 화면 (구현됨)

- `app/components/AdminSettings.tsx`의 `AppSettingsCards`가 카드 세 개(알림 메일 발송, 가입 승인 방식, 알림 메일 제목)를 그리고, `Settings.tsx`의 "관리자 설정" 영역에서 `SenderCard` 옆 2열 그리드에 들어간다.
- 화면은 API 라우트 없이 **브라우저에서 RLS로 바로 읽고 쓴다** (`upsert`). 관리자 확인은 RLS 정책이 한다.
- 기존 `SectionCard`, `Switch`, `ToggleGroup`, `Input`/`InputGroup`, `Badge`, `Button`을 썼다.
- 저장 성공·실패는 토스트로 알리고, 실패하면 화면 값을 이전 상태로 되돌린다.

## 확인 필요

- 실제 운영에서 일시정지 → 재개 흐름을 한 번 돌려 보지는 않았다 (단위 테스트로만 확인).
- 도메인 자동 승인 + 카카오 로그인처럼 이메일 인증 여부가 제공처마다 다른 경우의 동작은 카카오 로그인 설계(`2026-11-06-kakao-login-design.md`)에서 함께 확인해야 한다.
